# Clone Convergence and SPIMAR Adaptation Map

**Document ID:** `SPM-HIF-MERGE-001`  
**Status:** `IMPLEMENTATION_STRATEGY_LOCKED_MAPPING_AWAITS_REPOSITORY_AND_PARITY`

## 1. Controlling strategy

The final website begins from the House of Yellow cloned implementation foundation. The Phase 08 package expands and transforms that foundation into SPIMAR; it does not create a separate production website.

The merge order is mandatory:

1. identify the clone repository, branch, deployed commit, build, and environment;
2. repair missing media, poster fallbacks, staging indexation protection, and other P0 defects;
3. complete and approve route/state/viewport parity for the reference foundation;
4. extract neutral layout, component, media, motion, and responsive primitives;
5. remove House of Yellow brand, navigation, content, contacts, claims, analytics IDs, and business-specific data;
6. map every `HIF`/`UXF` target to a neutral clone primitive or a new SPIMAR component;
7. implement the approved SPIMAR sitemap, content objects, states, multilingual behavior, CMS/CRM, and forms;
8. run visual regression, functional, accessibility, performance, security, content, and analytics QA.

## 2. Preserve, replace, extend

| Foundation layer | Action | Rule |
|---|---|---|
| Layout engine and responsive scaffolding | `PRESERVE_AFTER_PARITY` | Keep only when it supports Phase 07/08 hierarchy, RTL, reflow, and accessibility |
| Premium media planes and crop behavior | `PRESERVE_AND_HARDEN` | Add poster/error/reduced-motion/rights contracts; no broken dark hero |
| Motion orchestration | `PRESERVE_INTENT_RECALIBRATE_VALUES` | Keep craft and continuity; SPIMAR semantics and reduced motion control timing |
| Reusable navigation primitives | `NEUTRALIZE_AND_REMAP` | Replace House of Yellow IA with global/local SPIMAR shells |
| Typography setup | `REPLACE_OR_RELICENSE` | Use approved SPIMAR Latin/multilingual families; do not inherit unlicensed fonts |
| Color tokens | `REPLACE` | Lock SPIMAR Gold `#EFC337`, Black `#000000`, controlled neutrals/semantics |
| Brand, copy, claims, contact details | `REMOVE_COMPLETELY` | No House of Yellow production residue |
| Page templates | `REMAP_AND_EXTEND` | Reuse structural primitives; Phase 03 routes and 17 template families control |
| Events, proof, offers, resources | `NEW_STRUCTURED_CONTENT` | Driven from the SPIMAR content model and readiness states |
| Exhibitor/visitor forms and confirmations | `NEW_PRODUCT_WORKFLOWS` | Durable-first submission and outcome distinctions are mandatory |
| CMS/CRM/provider integrations | `NEW_PRODUCT_INFRASTRUCTURE` | Production selection remains reversible until architecture gate |
| Multilingual/RTL | `EXTEND_FOUNDATION` | Explicit FR/EN/AR routes, semantic equivalence, true RTL |
| Legal, privacy, accessibility, recovery | `NEW_OR_EXTENDED` | Must follow SPIMAR ownership and release contracts |

## 4. Definition of merge-ready

The project is merge-ready only when:

- Gate 8 approves the complete Phase 08 package;
- the clone repository/branch/commit/build identity is recorded;
- House of Yellow reference parity passes, including media and staging protection;
- neutral primitives are documented with source paths and tests;
- every `HIF-001`–`048` has a primitive/new-component mapping and content/provider dependencies;
- no production House of Yellow data remains;
- implementation stories include visual, functional, responsive, RTL, accessibility, content, and state acceptance.

## 5. Non-negotiable outcome

The final result is one expanded SPIMAR website foundation: premium in the same craft class as the approved clone reference, but structurally, visually, editorially, operationally, and technically controlled by the CTO specification and the approved SPIMAR product system.
