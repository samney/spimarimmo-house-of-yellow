# Representative Identity Applications and RTL Check

**Document ID:** `SPM-ID-APPLY-001`  
**Status:** `APPROVED_FOR_SYSTEM_PRODUCTION_AT_GATE_6`  
**Date:** 31 July 2026

## 1. Purpose

Phase 06 applies each territory to a small representative set of approved Phase 05 wireframes. The objective is to judge brand fit, hierarchy, content resilience, and multilingual behavior before designing the full site.

These are identity studies, not final high-fidelity screens.

All applications use the same fixed SPIMAR Gold `#EFC337`, Black `#000000`, white, and gray neutral system. Territory changes affect composition and content emphasis—not palette.

## 3. Stable structure across territories

Art direction cannot change:

- route or template ownership;
- exhibitor-first homepage priority;
- the one canonical event family;
- lifecycle, exhibitor-sales, visitor-registration, and provider-readiness separation;
- CTA outcome semantics;
- proof definitions and source proximity;
- form purpose, recipient, context, consent, or durable-submission behavior;
- mobile, RTL, reduced-motion, closed, empty, error, and provider-failure meaning.

## 4. Application behavior by territory

### 4.1 Global homepage first view — `UXF-001`

| Territory | First-view composition | What must remain visible |
|---|---|---|
| `IDT-01` | Large edition/city field, documentary event crop, short B2B promise, gold exhibitor action, next-edition rail | Parent navigation, audience, active edition/state, event proof cue, truthful exhibitor CTA |
| `IDT-02` | Morocco/host-city paired media, route/index treatment, warmer narrative line, decisive edition panel | Event mechanics must not be displaced by emotional story |
| `IDT-03` | Proposition and method/evidence preview in a precise editorial grid | Live event atmosphere and city/date cannot disappear into a data layout |

### 4.2 Canonical event overview — `UXF-016`

| Layer | Visual treatment |
|---|---|
| Event identity | City, country, date range, venue/status, lifecycle label |
| Exhibitor path | Proposition, sales availability, offer/proof links, qualified request action |
| Visitor path | Programme/participants/practical information, registration availability, pre-registration action |
| Shared truth | One canonical event record; no duplicated facts or contradictory status badges |
| Fallback | Postponed/cancelled/completed/closed/unknown/provider-unavailable variants remain deliberately composed |

`IDT-01A` should use Signal for the event header, Cities for location and human story, and Proof for availability, evidence, and decision modules.

### 4.3 Proof/case hub — `UXF-011`

The proof composition must visibly separate:

1. what was expected;
2. what was delivered;
3. what was measured;
4. how the measure is defined;
5. source and period;
6. caveat/status;
7. related event/offer/action.

`IDT-03` controls this content mode inside the recommended identity. Gold marks selection or next action; it does not certify a metric.

### 4.4 Offer comparison — `UXF-008`

- compare identical capability rows;
- distinguish available, included, optional, proposal-only, unavailable, and terms-required through labels and shape;
- do not show invented prices;
- keep package context through meeting/enquiry transitions;
- use a reading-order alternative on narrow screens;
- do not turn the page into a generic SaaS pricing table.

## 5. Working multilingual headline test

These lines are composition fixtures only.

### French

`Présentez vos projets marocains sur les marchés internationaux les plus pertinents.`

### English

`Present your Moroccan projects in the international markets that matter.`

### Arabic

`قدّموا مشاريعكم العقارية المغربية في الأسواق الدولية الأكثر صلة.`

Review questions:

- Is the audience and business action clear before the media finishes loading?
- Can the display system handle a longer French line without shrinking excessively?
- Does Arabic retain authority with natural line breaks and no simulated condensed Latin form?
- Are the city/date and primary action still visible above the fold at the target composition?
- Does the English version avoid awkward oversized single words?

Final copy requires commercial/editorial approval and fluent Arabic review.

## 6. Arabic RTL identity check

| Element | Required behavior | Reject if |
|---|---|---|
| Wordmark | Preserve official mark orientation; compose with Arabic UI | Mark or photography is mirrored |
| Navigation | Logical RTL order and focus; locale/host meaning preserved | Visual order differs from keyboard/screen-reader order |
| Hero | Arabic headline receives intentional line breaks; event/date/actions remain grouped | Latin layout is merely flipped or type is compressed |
| City/date | Arabic/Latin place names and numerals use isolated direction runs | Punctuation, ranges, or numerals reorder incorrectly |
| CTA | Outcome-equivalent Arabic label; adequate width and touch area | Shortened label changes the actual action |
| Event paths | Exhibitor and visitor choices remain semantically distinct | Color becomes the only distinction |
| Evidence | Definitions, source, period, and caveat align logically | Mixed-direction values interrupt reading order |
| Forms | Labels, help, errors, consent, and focus follow logical RTL flow | Placeholders become the only labels |
| Media | Real images remain unmirrored; captions align with language | Visual evidence is reversed or context is lost |
| Motion | Direction follows reading/interaction only where meaningful | Geographic route is incorrectly reversed |

## 7. Mobile identity check

For `UXF-003` and other mobile targets:

1. show city/date/status before ornamental campaign copy;
2. retain a short B2B proposition and one primary action;
3. choose one dominant media crop with a real mobile poster;
4. move proof and secondary events into deliberate sequences;
5. avoid overlapping type that depends on one language length;
6. allow one contextual persistent action only after the original action leaves view;
7. never cover consent, errors, legal text, or system feedback;
8. retain a non-motion equivalent.

## 8. Missing-content resilience

| Missing input | Identity response |
|---|---|
| Hero video | Approved poster; if absent, purposeful typographic edition composition |
| Event photography | City/date/type composition plus verified practical facts; no generated “historical” crowd |
| Metrics | Remove the metric block or show an approved qualitative deliverable with no fake value |
| Partner logos | Remove the wall and retain owned proof/method; never show anonymous logo placeholders publicly |
| Price | Proposal-only language and equal capability comparison |
| Testimonial | Use case/process evidence; do not fabricate a quote |
| Locale content | Clear fallback or unavailable state; do not silently mix critical languages |
| Provider | Durable submission state and disclosed delayed/manual fallback |

## 9. Gate 6 review protocol

Review the same application set for each territory and record:

- first five-second interpretation;
- event/property/trust/Morocco signals recognized;
- perceived primary audience;
- clarity of next action and expected outcome;
- brand distinctiveness;
- desktop/mobile/RTL integrity;
- credibility with missing or unapproved content;
- specific issue linked to `UXF`, `BRI`, or territory ID.

Use `P0/P1/P2/P3` severity. A `P0/P1` issue affecting meaning, audience, action, lifecycle, evidence, or accessibility must be corrected before Phase 07 tokenization.
