# 03 — Gated Implementation Sequence

Do not collapse these gates into one large redesign pass.

## Gate 0 — Repository and baseline audit

Required:

- inspect repository instructions;
- verify branch, SHA and working tree;
- find accepted visual foundation;
- locate current method section;
- inventory fonts, tokens, motion and media utilities;
- run current build, typecheck, lint and relevant tests;
- record pre-existing failures;
- define owned files.

Exit evidence:

- `WORKFLOW_READY=true` checkpoint;
- baseline SHA;
- commands and results;
- implementation plan.

## Gate 1 — Three-state schema and shared shell

Implement:

- types;
- complete three-phase data;
- semantic section shell;
- introduction;
- stage layout regions;
- accessible phase control;
- stable visual-test state selection.

Do not implement full Phase 02 or Phase 03 visuals yet.

Exit evidence:

- component tree;
- Phase 01/02/03 content tests;
- no duplicated full-phase JSX.

## Gate 2 — Phase 01 static parity

Implement at `1536 × 1024`:

- Phase 01 rail state;
- Phase 01 copy and chips;
- dossier base;
- Phase 01 document layers;
- Phase 01 status rail;
- Phase 01 deliverable cards and connectors;
- footer progress;
- contextual and global CTA.

Animations remain disabled for this gate.

Exit evidence:

- reference screenshot;
- actual screenshot;
- overlay/diff;
- measured delta list;
- parity verdict.

Gate 2 must pass before Phase 02/03 visual work.

## Gate 3 — Phase 01 correction pass

Correct in this order:

1. overall canvas and stage geometry;
2. grid columns and anchors;
3. typography and line wrapping;
4. dossier scale and layer positions;
5. deliverable stack;
6. connector geometry;
7. borders, radii, shadows and grain;
8. micro-alignment.

Exit evidence:

- final Phase 01 diff;
- zero unreviewed material deltas.

## Gate 4 — Phase 02 and Phase 03 static states

Reuse the locked geometry. Change only approved phase content and layers.

Exit evidence:

- deterministic screenshots for all three phases;
- geometry stability assertion;
- all content contract tests pass.

## Gate 5 — Motion and state synchronization

Implement:

- scroll progression;
- click/tap selection;
- keyboard selection;
- dossier document transitions;
- status and deliverable transitions;
- reduced-motion mode;
- prevention of scroll/click state conflicts.

Exit evidence:

- interaction tests;
- reduced-motion capture;
- console free of runtime errors.

## Gate 6 — Responsive recomposition

Implement and validate:

- wide desktop;
- standard desktop;
- tablet;
- small mobile;
- large mobile;
- touch and keyboard behavior.

Exit evidence:

- screenshots at agreed breakpoints;
- no overflow;
- no clipped content;
- equivalent content across breakpoints.

## Gate 7 — CMS integration

- connect approved fields;
- constrain layout-affecting content;
- validate media fallbacks;
- preserve static fallback data if required by the project;
- verify CTA destinations and CRM boundaries.

## Gate 8 — Final validation and handoff

Run:

- formatter;
- lint;
- typecheck;
- unit/component tests;
- browser tests;
- production build;
- visual-regression suite;
- accessibility scan;
- route coverage where applicable.

Deliver:

- exact SHA and branch;
- files changed;
- commands and outcomes;
- screenshots and diffs;
- known intentional deltas;
- performance/accessibility notes;
- next eligible work.
